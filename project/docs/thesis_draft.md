## 摘要

随着汽车使用场景的不断扩展，车内空气质量、烟雾污染以及有害气体异常等问题逐渐受到重视。传统的车内环境判断方式主要依赖人工感知，不仅主观性较强，而且难以及时发现污染加重、空气恶化和局部异常等情况。针对上述问题，本文设计并实现了一种基于 STM32F103C8T6、MQ-135 气体传感器、ESP-01S Wi-Fi 模块和 Raspberry Pi 4B 的车内环境监测与预警系统，实现了车内环境数据采集、本地声光报警、无线传输和远程查询等功能。

系统以 STM32F103C8T6 单片机为核心控制器，使用 MQ-135 传感器对车内环境污染程度进行检测，并通过 ADC 对模拟信号进行采样。为提高采样稳定性，系统在软件中引入多次采样平均和滑动平均滤波算法，对原始数据进行平滑处理；随后依据设定阈值对环境状态进行分级，并结合滞回机制生成报警状态，避免临界点附近频繁抖动。对于超过预警阈值的情况，系统采用创乐博 RGB 小灯的红色通道进行视觉提示，并通过 S8550 三极管驱动蜂鸣器完成声报警。与此同时，STM32 通过 ESP-01S 将监测数据以 TCP 方式上报至 Raspberry Pi 4B 服务器端，树莓派再提供最新数据和历史数据的 HTTP 查询接口，实现远程监测。

本文围绕系统需求分析、总体方案设计、硬件电路设计、软件模块实现以及系统测试等方面展开论述。测试结果表明，该系统能够稳定完成环境数据采集、污染等级判断、本地报警和远程传输任务，具有结构清晰、实现成本较低、扩展性较好等特点，可为车内环境监测类嵌入式系统设计提供一定参考。

关键词：STM32F103C8T6；MQ-135；ESP-01S；Raspberry Pi 4B；车内环境监测；无线预警

## ABSTRACT

With the continuous expansion of vehicle application scenarios, in-cabin air quality and harmful gas monitoring have become increasingly important. Traditional judgment of cabin environmental conditions mainly depends on human perception, which is subjective and cannot provide timely warning when pollution becomes severe. To solve this problem, this paper designs and implements an in-cabin environmental monitoring and warning system based on the STM32F103C8T6 microcontroller, MQ-135 gas sensor, ESP-01S Wi-Fi module, and Raspberry Pi 4B.

The system takes STM32F103C8T6 as the core controller and uses the MQ-135 sensor to detect environmental pollution level in the vehicle cabin. The analog signal is sampled by ADC, and a combination of multi-sample averaging and moving average filtering is used to improve stability. According to preset thresholds, the filtered data are classified into different environmental levels, and a hysteresis strategy is introduced to prevent frequent alarm jitter near the threshold. When the measured value exceeds the warning range, the red channel of the RGB indicator lamp is turned on and the buzzer driven by an S8550 transistor is activated for audible warning. At the same time, STM32 transmits telemetry data to the Raspberry Pi 4B through the ESP-01S module over TCP. The Raspberry Pi server then provides HTTP interfaces for querying the latest data and historical records, thereby supporting remote monitoring.

This paper discusses the system from the aspects of requirement analysis, overall architecture design, hardware implementation, software module design, and system testing. The test results show that the system can reliably accomplish environmental data acquisition, level classification, local warning, and remote transmission. The system features a clear structure, low implementation cost, and good scalability, and it can provide a practical reference for similar embedded vehicle environment monitoring applications.

Key words: STM32F103C8T6; MQ-135; ESP-01S; Raspberry Pi 4B; in-cabin environment monitoring; wireless warning

## 1 引言

### 1.1 研究背景与意义

随着汽车逐步由单一交通工具向智能化、网联化终端演进，车内环境安全问题也日益受到关注。在密闭或半密闭的车内空间中，若空气流通条件较差，烟雾、有机挥发物、尾气渗入以及其他污染气体累积，容易引发驾驶疲劳、乘坐不适甚至安全隐患。因此，设计一种能够对车内环境污染程度进行实时检测、及时报警并支持远程查看的低成本嵌入式系统，具有较强的现实意义。

从应用角度看，车内环境监测系统既可用于普通乘用车，也可扩展到校车、物流运输车辆、网约车以及封闭空间移动设备等场景。通过在本地完成预警，并将数据上传至上位端或边缘网关，管理者可以更加及时地掌握环境变化趋势。从教学和工程实践角度看，该课题综合运用了传感器接口技术、单片机控制技术、串口通信技术、无线网络传输技术以及嵌入式软件设计方法，具有较好的综合训练价值。

## 2 系统需求分析

### 2.1 系统功能需求分析

结合课题目标，系统应满足以下基本功能需求：

1. 能够实时采集 MQ-135 输出的模拟电压信号，并转换为数字量。
2. 能够对采样结果进行滤波处理，降低噪声对判定结果的影响。
3. 能够根据设定阈值对环境污染程度进行分级。
4. 当环境污染程度超出预警范围时，能够触发本地灯光和蜂鸣器报警。
5. 能够通过 Wi-Fi 将监测数据从 STM32 传输至 Raspberry Pi 4B。
6. 树莓派能够保存最近一段时间的数据，并提供最新数据与历史数据访问接口。
7. 系统应具备一定的异常恢复能力，在网络掉线后能够重新建立连接。

### 2.2 系统性能需求分析

除基本功能外，系统还应满足一定的性能要求：

1. 采样与上报周期应保持在秒级，以满足实时性要求。
2. 数据处理逻辑应足够简单稳定，便于在资源受限的单片机平台上运行。
3. 报警判断应避免阈值附近频繁切换，减少误报和抖动。
4. 通信方式应具有较好的兼容性，使树莓派能够方便地接收与转发数据。
5. 服务器端应支持最近数据缓存，便于后续扩展网页可视化或移动端显示。

### 2.3 硬件需求分析

本系统主要由以下硬件组成：

1. 主控模块：STM32F103C8T6，负责数据采样、逻辑处理、报警控制和通信调度。
2. 传感器模块：MQ-135 气体传感器，用于检测车内环境污染程度，适用于对空气质量变化进行趋势性判断。
3. 无线通信模块：ESP-01S，负责将 STM32 端处理后的数据通过 Wi-Fi 发送到树莓派。
4. 本地显示与报警模块：创乐博 RGB 小灯和蜂鸣器。其中 RGB 小灯在本系统中主要使用红色通道作为超阈值告警指示，蜂鸣器通过 S8550 三极管驱动。
5. 服务端模块：Raspberry Pi 4B 4GB 版本，负责接收 TCP 数据并通过 HTTP 接口对外提供查询服务。

### 2.4 软件需求分析

从软件划分角度，系统可分为嵌入式端软件和树莓派服务端软件两部分。

嵌入式端软件需要完成系统时钟初始化、GPIO 初始化、ADC 初始化、串口初始化、环境数据处理、报警控制以及 ESP-01S 状态机驱动等任务。树莓派服务端软件需要完成 TCP 监听、数据帧解析、历史数据缓存、HTTP 服务响应等功能。

### 2.5 通信与数据格式需求分析

为了保证嵌入式端和服务端之间的数据交换简单可靠，本系统采用文本行协议进行传输。STM32 每次完成一次数据处理后，生成一行遥测字符串，并通过 ESP-01S 上传至树莓派。数据格式如下：

```text
T,<ts>,<adc_raw>,<adc_filt>,<idx>,<alarm>
```

其中，`ts` 表示时间序号，`adc_raw` 表示原始采样值，`adc_filt` 表示滤波后的采样值，`idx` 表示环境等级索引，`alarm` 表示当前报警状态。该格式简洁、易解析，既便于嵌入式端生成，也便于树莓派端进行存储与接口转发。

### 2.6 本章小结

本章从功能、性能、硬件、软件和通信格式等方面对系统进行了需求分析。可以看出，本课题不仅需要实现车内环境数据采集，还需要兼顾本地告警、远程传输和服务端查询，属于一个包含感知层、控制层、网络层和应用层的完整小型物联网系统。

## 3 系统概要设计

### 3.1 系统总体方案

根据前述需求，本文采用“传感采集端 + 无线传输端 + 边缘服务端”的总体设计思路。系统工作流程如下：MQ-135 对环境污染变化进行感知，输出模拟电压信号；STM32F103C8T6 通过 ADC 完成采样，并在本地执行滤波、分级和报警逻辑；处理后的数据通过 ESP-01S 使用 Wi-Fi 网络发送到 Raspberry Pi 4B；树莓派接收数据后缓存最近历史记录，并通过 HTTP 接口向外提供最新值与历史值查询。

## 4 系统详细设计

### 4.1 主控模块设计

系统主控采用 STM32F103C8T6 单片机。该芯片基于 ARM Cortex-M3 内核，具有较好的处理性能、丰富的外设资源和较高的性价比，能够满足本课题对 ADC 采样、串口通信、GPIO 控制和定时调度的需求。系统上电后首先调用 HAL 库初始化，然后配置系统时钟为外部 8 MHz 晶振经 PLL 倍频后的 72 MHz，为后续模块运行提供稳定时钟基础。

在程序结构上，主函数首先完成 GPIO、USART、ADC、遥测模块、应用层模块和 ESP 模块初始化；随后在无限循环中持续执行 ESP 状态机维护，并按 1 s 周期执行一次应用层任务。该结构简单清晰，适合本系统这类周期性采样与异步通信并存的应用场景。

### 4.2 传感器采样与数据预处理设计

MQ-135 为模拟量输出传感器，适用于空气质量和多种气体变化趋势的检测。本系统中，传感器模拟输出连接至 STM32 的 `PA0` 引脚，对应 `ADC_CHANNEL_0`。在软件设计中，为提高数据稳定性，系统并未直接使用单次 ADC 转换结果，而是先进行了 16 次采样求平均，再将结果送入后续环境处理模块。

其平均采样过程可表示为：

```text
adc_raw = (x1 + x2 + ... + x16) / 16
```

多次采样平均能够在一定程度上降低电源波动、传感器瞬时抖动及环境噪声带来的影响，为后续阈值判定提供更平稳的输入数据。

### 4.3 滤波与环境分级设计

为了进一步提高数据稳定性，系统在原始平均值基础上使用长度为 5 的滑动平均滤波。系统维护一个循环缓冲区保存最近若干次采样结果，并实时更新累加和。当新样本进入时，若缓冲区未满，则直接累加；若缓冲区已满，则先减去最旧值，再加入新值，从而完成滤波输出计算。

滤波后，系统根据阈值对环境状态进行三级划分：

1. 当滤波值小于 `1000` 时，判定为良好状态。
2. 当滤波值在 `1000` 到 `1100` 之间时，判定为预警状态。
3. 当滤波值大于 `1100` 时，判定为污染较重状态。

为了便于后续传输和显示，系统将等级映射为索引值：

1. 良好状态映射为 `20`。
2. 预警状态映射为 `60`。
3. 污染较重状态映射为 `90`。

该设计兼顾了工程可实现性和数据表达简洁性，便于服务端直接解析和使用。

### 4.4 报警策略设计

如果仅依据阈值直接触发报警，那么当滤波结果在阈值附近来回波动时，系统会频繁进入和退出报警状态，影响用户体验。因此，本文在报警逻辑中引入了滞回机制。具体做法为：

1. 当系统处于非报警状态时，若滤波值大于 `1100`，则进入报警状态。
2. 当系统已经处于报警状态时，只有当滤波值回落至 `1100-5` 以下时，才解除报警。

上述设计避免了报警抖动，使系统在临界区域的行为更稳定。

在本地提示方式上，系统采用声光结合方式：

1. 当报警状态由无变有时，蜂鸣器触发三声提示。
2. 当滤波结果持续高于预警阈值时，红色指示灯保持点亮。

蜂鸣器驱动采用 S8550 三极管，以解决单片机 IO 口直接驱动能力有限的问题。软件中采用 1 ms 节拍维护蜂鸣器状态机，实现每次鸣叫 200 ms、间隔 200 ms、共三次的提示效果。

### 4.5 串口与 ESP-01S 通信设计

ESP-01S 通过 USART1 与 STM32 相连，其中 `PA9` 为发送引脚，`PA10` 为接收引脚，串口波特率设置为 `115200`。系统采用中断接收方式，将 ESP 返回的数据逐字节写入环形缓冲区，再通过关键字匹配方式判断当前指令执行结果。

ESP 模块软件采用状态机方式实现，主要包括以下状态：

1. `AT` 测试状态：验证模块是否在线。
2. `SET_MODE` 状态：配置为 STA 模式。
3. `JOIN_AP` 状态：连接指定 Wi-Fi 热点。
4. `SET_MUX` 状态：配置为单连接模式。
5. `TCP_CONNECT` 状态：连接树莓派服务器。
6. `RUN` 状态：周期性发送遥测数据。
7. `RETRY` 状态：在失败后延时重试。

该状态机设计保证了系统在网络异常、模块掉线或发送失败等情况下能够自动恢复，增强了系统的稳定性和可用性。

### 4.6 遥测数据封装设计

在完成采样、滤波、分级和报警判断后，系统将当前结果封装为一行文本。数据内容包括时间序号、原始 ADC 值、滤波 ADC 值、等级索引和报警状态。采用文本协议的优点在于：

1. 数据格式直观，调试方便。
2. 树莓派端可以直接使用字符串解析函数完成处理。
3. 后续如需接入网页或数据库，也可以较容易扩展。

系统当前输出格式为：

```text
T,ts,adc_raw,adc_filt,idx,alarm
```

其中 `ts` 随 1 s 周期递增，可作为顺序时间标识。

### 4.7 Raspberry Pi 4B 服务端设计

树莓派端采用 C 语言编写轻量级服务程序，在 Raspberry Pi 4B 4GB 平台上运行。服务端包含两个线程：

1. TCP 服务线程：监听 `9000` 端口，接收来自 ESP-01S 的遥测文本行。
2. HTTP 服务线程：监听 `8080` 端口，对外提供数据接口。

服务端在接收到一行遥测数据后，先解析出 `ts`、`adc_raw`、`adc_filt`、`idx` 和 `alarm` 字段，然后更新最新样本，并写入历史缓存区。历史缓存采用固定容量循环数组实现，当前容量设置为 `120` 条。HTTP 接口包括：

1. `/latest`：返回最近一次接收到的遥测数据。
2. `/history?limit=n`：返回最近若干条历史数据，默认返回 `24` 条。

该设计使树莓派既充当无线接收端，又承担简单边缘服务功能，为后续扩展网页展示、报警记录分析和可视化界面奠定了基础。

[占位符：此处插入树莓派服务端运行界面截图]

### 4.8 关键实现特点分析

与只做单片机本地显示的监测方案相比，本文系统具有以下实现特点：

1. 形成了“采集、处理、报警、传输、查询”一体化链路。
2. 在单片机端加入了多级滤波和滞回判断，提高了报警稳定性。
3. 使用状态机管理 ESP-01S 的联网与发送流程，增强了系统鲁棒性。
4. 利用树莓派提供边缘服务功能，使系统具备远程访问能力。

### 4.9 本章小结

本章对系统的关键硬件接口、滤波算法、报警逻辑、ESP 状态机、遥测协议和树莓派服务端实现进行了详细说明。通过这些模块的协同工作，系统完成了从传感采集到远程访问的完整功能闭环。

## 结论与展望

本文围绕车内环境监测与预警需求，设计并实现了一套基于 STM32F103C8T6、MQ-135、ESP-01S 和 Raspberry Pi 4B 的小型物联网监测系统。系统完成了环境污染程度采集、数据滤波处理、阈值分级、声光报警、无线传输和服务端查询等功能。通过模块化设计和分层实现，课题较好地将单片机控制、无线通信和边缘服务结合起来，形成了完整的工程闭环。

从实际测试情况来看，本系统具备以下优点：结构简单清晰、软硬件实现成本较低、调试方便、扩展能力较强。特别是在树莓派端加入 TCP 接收与 HTTP 查询功能后，系统已不再局限于本地单片机实验，而具备了一定的远程监测能力。

但系统仍存在进一步完善空间：

1. MQ-135 更适合环境污染趋势检测，若需要更高精度定量测量，还可增加专用气体传感器或进行标定补偿。
2. 当前服务端仅实现轻量级缓存与接口返回，后续可进一步增加数据库存储、网页可视化和报警日志管理。
3. 现有系统主要基于固定阈值判断，后续可以引入温湿度补偿、自适应阈值或简单智能分析方法，提高判定精度。
4. 当前指示灯仅使用 RGB 模块中的红色通道，后续可扩展为多颜色状态提示，提高交互性。

总体而言，本文完成了课题预定目标，验证了所选技术路线的可行性，为后续在车载环境监测方向上的进一步扩展提供了实现基础。
